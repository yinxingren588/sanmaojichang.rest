同一客户端发布多个安装包时，应先查看设备架构，再按项目安装说明选择。看到“64 位”不能立刻把 x64 与 arm64 当成同一类资产；设备、系统和应用支持需要对应起来。

## 先记录设备信息

在 Windows 设置的系统信息或“关于”页面查看系统类型、处理器和系统版本。不同版本的入口名称可能调整，目标是取得架构信息，而不是记住某一个按钮位置。单位管理的设备还应遵循组织的软件安装要求，不自行变更管理策略。

## 把发布资产分成三组

先按操作系统筛选，再按架构筛选，最后区分安装器、便携包和源代码。举例说，假设发布页同时有 Windows x64、Windows arm64 与 macOS arm64 资产，最后一项即使同样写 arm64，也不是 Windows 安装包。文件扩展名与发布说明应一起看。

## 核对应用支持而不是反复尝试

项目声明的最低系统版本、架构支持和依赖条件，是继续安装前需要确认的材料。若设备架构与发布资产不对应，先寻找项目明确支持的版本，不通过改扩展名或来源不明补丁尝试运行。不要把启动失败立即归因于订阅或节点，它可能还没有进入网络阶段。

## 安装后验证三个结果

确认应用可以正常启动、版本信息与所选发布标签对应、配置页面可以打开。此时再按[首次订阅导入](/guides/subscription-first-import/)添加自己的兼容配置。启动成功只是软件安装的结果，不能作为订阅已经可用或线路质量良好的证据。

## 选错安装包怎样恢复

如果尚未运行，停止安装并重新选择正确资产；若已安装但无法启动，先保存错误文本与版本，按项目卸载说明处理，再安装支持的版本。不要清空所有系统网络组件。下载安装前的文件核对可以参考[下载与校验教程](/guides/download-integrity/)，将身份、架构和配置三个问题分开解决。
